# Flutter Integration Guide

This guide details how the mobile application should consume the REST APIs provided by the SecureAttend backend. It is the authoritative reference for the mobile engineering phase.

## Base Configuration

1. **Environment Variables**:
   During development over a local network, the API base URL must be dynamically provided using `--dart-define`.
   ```bash
   flutter run --dart-define=API_BASE_URL=http://<YOUR_LAPTOP_IP>:8000/api/v1
   ```
2. **Cleartext Traffic**:
   Ensure `AndroidManifest.xml` has `android:usesCleartextTraffic="true"` inside the `<application>` tag during local LAN testing.

## 1. Authentication & Tokens
The application uses JWT (JSON Web Tokens).

- **Login**: `POST /auth/login` returns an `access_token` and `refresh_token`.
- **Storage**: Store both securely using `flutter_secure_storage`.
- **Injection**: Inject `Authorization: Bearer <access_token>` into every protected request.
- **Refresh Flow**:
  - Intercept any `401 Unauthorized` response.
  - Pause all outgoing requests.
  - Call `POST /auth/refresh` using the stored `refresh_token`.
  - Update storage with new tokens.
  - Retry the queued requests.
  - If the refresh request fails (e.g., token expired), forcibly log the user out and clear storage.

## 2. Student Attendance Flow (Strict Sequence)

The mobile client must never bypass these steps:

1. **Get Challenge**: `POST /api/v1/student/face-verification/challenge`
   - Response: `{"challenges": ["blink", "look_left"]}`
2. **Capture**: Display liveness instructions and capture the required media (images).
3. **Verify Face**: `POST /api/v1/student/face-verification/verify`
   - Payload: Multipart form data with the image(s).
   - Response: `{"face_proof_token": "abc123xyz...", "expires_in": 60}`
   - *If this fails, display the exact error message provided by the API (e.g., "Multiple faces detected").*
4. **Scan QR**: Open the mobile scanner. Upon reading the QR, pause the scanner.
   - Example payload from QR: `{"qr_token": "qr789def..."}`
5. **Submit**: `POST /api/v1/student/attendance/mark/mark`
   - Payload: `{"qr_token": "qr789def...", "face_proof_token": "abc123xyz..."}`
   - Success: 200 OK. Show receipt.
   - Failure: Map the error code (e.g., `attendance/duplicate-submission`) to a user-friendly message.

## 3. Faculty Dynamic QR Flow

The faculty device acts as a "dumb terminal" displaying tokens generated by the server.

1. **Start Session**: `POST /api/v1/faculty/attendance-sessions` (Payload: `{"schedule_id": 42}`)
   - Response: `{"session_id": "sess_1", "current_qr": "qr123...", "expires_at": "2026-07-07T12:05:00Z"}`
2. **Render**: Display `current_qr` using `qr_flutter`.
3. **Refresh**: 
   - Use the `expires_at` timestamp.
   - Set a Dart `Timer` to call `GET /api/v1/faculty/attendance-sessions/{session_id}/qr` a few seconds before expiration.
   - Update the QR code UI with the new token.
4. **Live Polling**: `GET /api/v1/faculty/attendance-sessions/{session_id}/live` every 5 seconds to update the present count.
5. **End Session**: `POST /api/v1/faculty/attendance-sessions/{session_id}/end`
